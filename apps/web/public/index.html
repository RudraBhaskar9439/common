HOW IT WORKSFOUR STEPS
  1. An agent asks

    “Which open model can run this support desk?” Common checks shared memory for a matching, fresh report.

  2. If nothing exists, reserve and pay

    The contract claims the purchase atomically. On testnet, 0.5 HBAR settles through x402 before any compute runs.

  3. The evaluation runs

    Each model gets a browser and five tasks. Deterministic checks inspect the final state — no model grades another model.

  4. The next agent reuses it

    Same configuration, still fresh, delivered successfully → the report is handed over. No payment, no wait.

    04 / LEDGER & RECEIPTS

    What was paid, and where to check.

    Every settled payment carries a Hedera transaction id you can verify independently on HashScan. Uncertain settlements stay blocked until reconciled — they are never retried blindly.

    OPERATIONS

    No operations recorded in this workspace.

    Agents hold no keys

    Requests never sign anything. One payment module signs, only against a matching on-chain reservation.

    One purchase per configuration

    The contract claims a purchase atomically. A competing request is refused, not duplicated.

    Payment ≠ delivery

    A paid job whose report fails stays paid and is recorded as such. Nothing repurchases automatically.

    Uncertainty is not failure

    If settlement is unclear, the operation waits for the chain to confirm. Reconciliation matches the exact signed transaction.
